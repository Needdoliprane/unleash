# Sources primaires — systèmes Rust, persistance et vérification

**Consultation : 16 novembre 2026.** Cette recherche précède les propositions des regards 2, 9 et 12. Le dossier décrit un produit à construire : aucune compilation d'Unleash, aucun essai de crash produit et aucune qualification macOS ne sont revendiqués. Une version affichée par une documentation est une observation, pas une dépendance déjà résolue dans un `Cargo.lock`.

## Décisions internes, non faits observés

Le writer dédié, les identifiants canoniques, les fencing epochs, les contrats de reprise, le process-host et l'admission atomique sont des décisions de ce dossier (ADR acceptés en R7), pas des faits observés. Leur justification est explicitée dans [l'audit Rust](../audits/rust-feasibility.md), [l'audit de persistance](../audits/persistence-and-recovery.md) et [l'audit QA](../audits/qa-verification.md). Leurs paramètres de latence, mémoire, débit et rétention sont des objectifs à mesurer. Aucune page citée n'établit qu'Unleash satisfait déjà ces objectifs.

Les URLs `latest` et les branches GitHub servent à rendre le contrôle reproductible aujourd'hui. L'implémentation devra figer compilateur, features, versions de crates, versions natives et empreintes source dans son manifeste de build, puis renouveler ce contrôle à chaque mise à jour. Les versions minimales sont fixées par l'amendement R7 d'[ADR-14](../architecture/adr/ADR-14-local-data-oss.md) (Q-11 : macOS 15.0 sur Apple Silicon, Ubuntu 24.04 LTS x86_64) ; leur qualification reste à produire (EXT-OS). Restent à prouver les capacités exactes de l'API externe AI-Guard (EXT-GUARD) et les mécanismes fournisseur pour réconcilier les requêtes interrompues.
